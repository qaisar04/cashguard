# CashGuard — AI-сервис контроля кассовой дисциплины по видео

Решение кейса ForteBank (Datathon 26). Пользователь загружает `.mov` с записью рабочего места кассира, сервис
возвращает вердикт (`violation` / `no_violation`) и для каждого признака нарушения — тип, таймкод, описание,
1–3 кадра-доказательства и ссылку на нормативный источник. Вся обработка локальная, облачные AI-сервисы не используются.

```
cashguard/
├── api/    Spring Boot 3.5 (Java 17): публичный API, X-API-Key, загрузка, очередь задач, веб-интерфейс
├── ml/     FastAPI (Python 3.12): анализ видео — детектор + правила, нормативный каталог
├── docs/   normative-sources.md — проверенные акты НБРК и пункты-кандидаты для каждого типа
└── docker-compose.yml
```

## Быстрый старт

```bash
cp .env.example .env            # задайте CASHGUARD_API_KEY (ключ для жюри) и ML_API_KEY (внутренний)
docker compose up --build       # первая сборка ml скачивает веса (~1.2 ГБ) и запекает их в образ
open http://localhost:8080      # интерфейс; API — http://localhost:8080/api/v1
```

Проверка API (формат из ТЗ):

```bash
curl -X POST http://localhost:8080/api/v1/analyze -H "X-API-Key: $CASHGUARD_API_KEY" -F "file=@video_017.mov"
# {"job_id":"3f2a9c1e","status":"processing"}
curl http://localhost:8080/api/v1/jobs/3f2a9c1e -H "X-API-Key: $CASHGUARD_API_KEY"
# {"job_id":"3f2a9c1e","status":"done","verdict":"violation","violations":[{"type":"…","type_id":"…",
#   "timecode_sec":44.2,"description":"…","evidence_frames":[{"timestamp_sec":44.2,"image_base64":"/9j/…"}],
#   "rule":{"document":"…","clause":"","url":"https://adilet.zan.kz/…"}}]}
```

Отладка на одном видео (кадры с рамками + `observations.json` + `events.json`):

```bash
cd ml && .venv/bin/python scripts/debug_video.py ~/Downloads/open/videos/Х-22.mov --out debug/X-22
```

Запуск без Docker (разработка):

```bash
cd ml && python3.12 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/python scripts/download_weights.py                       # один раз, затем работает офлайн
ML_API_KEY=mlkey .venv/bin/uvicorn app.main:app --port 8000        # ML_OBSERVER=stub — без весов (контракт/фронт)

cd api && CASHGUARD_API_KEY=jurykey ML_API_KEY=mlkey ./mvnw spring-boot:run
```

Тесты: `cd api && ./mvnw test`, `cd ml && .venv/bin/pytest`.

## Архитектура

```
браузер / жюри ──X-API-Key──▶ api (Spring)                         ml (FastAPI)
                               POST /api/v1/analyze → job_id       POST /infer {video_path}
                               GET  /api/v1/jobs/{id}   ──────▶    видео → кадры (1 fps) → наблюдатели →
                               очередь (1 worker), TTL,            таймлайн состояний → правила → события
                               маппинг в JSON из ТЗ                + кадры-доказательства + нормативка
                               └── общий том ./data (видео) ──────┘
```

- **api** отвечает за всё, что видит жюри: ключ, загрузку, статусы `processing/done/failed`, таймаут 270 с
  (меньше лимита 5 мин), строгий JSON. Неизвестный `type_id` от ML — задача `failed`, а не «тихий» ответ.
- **ml** — чистый inference-сервис. Внутри: `pipeline/observers` (интерфейс `Observer.observe(frames) → Observation[]`,
  чтобы позже добавить VLM-наблюдатель для «денежных» типов), `pipeline/timeline` (состояние на каждую секунду:
  кто в зоне кассира, что на столе, экран, сейф, дверь), `pipeline/rules/*` (по модулю на тип),
  `rules/rules.json` (13 типов, русские названия, семейства, нормативный документ).
- ML-сервис также отдаёт тот же job-API (`/api/v1/analyze`, `/api/v1/jobs/{id}`) — для автономной работы и eval.

### Модели (все open source, коммерческие лицензии)

| Назначение | Модель | Лицензия |
|---|---|---|
| Люди, ноутбук/монитор, сумки (COCO-классы) | `PekingU/rtdetr_r50vd_coco_o365` (RT-DETR) | Apache-2.0 |
| Open-vocabulary детекция (наличные; сейф/дверь — экспериментально) | `google/owlv2-base-patch16-ensemble` (альтернатива: `IDEA-Research/grounding-dino-tiny`) | Apache-2.0 |
| Состояние экрана (погашен / экран блокировки / рабочее приложение); проверка «человек в комнате / отражение / за стеклом» | `openai/clip-vit-base-patch32`, zero-shot по кропу | MIT |

Лица не распознаются и не идентифицируются; звук не используется. Устройство выбирается автоматически (`cuda`/`mps`/`cpu`).

## Типы нарушений

Реализованы правилами (v1):

| type_id | Название | Что наблюдается |
|---|---|---|
| `workstation_unlocked` | Рабочая станция не заблокирована при уходе кассира | кассира нет у рабочего места ≥ 3 с, на экране — рабочее приложение |
| `valuables_left_unattended` | Ценности оставлены без присмотра | на столе наличные/сумка/папка, кассира нет ≥ 3 с |
| `safe_left_open` | Сейф оставлен открытым | открытый сейф, рядом никого ≥ 4 с |
| `cash_room_door_open` | Дверь кассы оставлена открытой | дверь открыта ≥ 4 с |
| `unauthorized_entry` | Посторонний в помещении кассы | входит ещё один человек во время обслуживания клиента или при открытой двери |
| `cash_exposed_to_visitor` | Наличные в открытом доступе при постороннем | наличные на столе, входит новый посетитель |

В каталоге (`ml/rules/rules.json`) есть ещё 7 типов (пересчёт, идентификация, инкассация, личные вещи, еда) — они
требуют понимания действий, а не состояний, и предназначены для следующего наблюдателя (локальная VLM с коммерческой лицензией).

## Нормативная база

`docs/normative-sources.md`: постановления Правления НБРК № 231 от 29.11.2019 (кассовые операции) и № 14 от 24.02.2020
(охрана и устройство помещений), с цитатами пунктов, наблюдаемых на видео. В ответе API поле `clause` пока пустое — пункт
вписывается после подтверждения трактовки командой, чтобы не выдавать непроверенные ссылки.

## Оценка на датасете

```bash
cd ml && .venv/bin/python scripts/evaluate.py \
  --labels ~/Downloads/labels_typed_v2.xlsx --videos-dir ~/Downloads/open/videos \
  --base-url http://localhost:8080 --api-key $CASHGUARD_API_KEY --out eval.csv
```

Отчёт: precision/recall/F1 по вердикту (все видео и отдельно по реализованным типам), MAE таймкода и доля попаданий
в ±2 с / ±5 с, точность типа, разбивка по `certainty`, число failed/timeout и максимальное время обработки.

## Ограничения и известные ошибки

- Роли «кассир/посетитель» определяются по положению относительно монитора, а не по идентификации человека. Новый трек
  считается посетителем, только если он родился у двери/края кадра и прошёл внутрь, либо CLIP классифицирует кроп как
  «человек в комнате»; треки, чья траектория зеркально повторяет траекторию другого человека, помечаются как отражение
  в стеклянной стене и не учитываются (`pipeline/tracking.py`).
- Полигон `zones.door` в `ml/config.yml` описывает полосу стеклянной двери/стены — при другом ракурсе его нужно
  переставить (`scripts/extract_frame.py` рисует сетку координат).
- `safe_left_open` и `cash_room_door_open` выключены по умолчанию (`rules.enabled`): zero-shot модели не отличают открытую
  дверь/сейф от закрытых на этой съёмке — нужен few-shot классификатор состояния по кропу, обученный на датасете.
- Детекция наличных zero-shot: порог (`score_threshold` у OWLv2) подбирается по датасету; при выключенном свете
  детекции слабеют.
- Экран: «приложение» vs «экран блокировки» различается CLIP по кропу — на мелком/бликующем экране возможны ошибки.
- Типы семейства «Деньги без проверки» в v1 не распознаются.
- Результат — подсказка для проверяющего, а не юридическое или дисциплинарное заключение.
